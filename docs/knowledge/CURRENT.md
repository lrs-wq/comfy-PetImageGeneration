# Comfy Pet Pipeline 当前知识

## 目标

上传一张必选宠物正面图和最多两张侧面图，先确定猫/狗物种并生成 canonical 身份参考，再生成相应动作 GIF/视频，同时尽量保持毛色、花纹、耳形、口吻、体型和尾形身份一致。

## 当前对外能力

- 简化 GIF API：端口 `8051`，同一 `/api` 端点使用 `type=upload` 提交、`type=query` 查询。
- 本地视频 API：端口 `8770`，路径 `/api/local-video`；公开入口为 `https://ai.hzzootech.com/api/local-video`，裸 IP 的 HTTP 默认站点按 Nginx 安全策略返回 `404`。
- ComfyUI：端口 `8188`，承担底层工作流执行。
- 测试平台：用于显式测试犬型及扩展动作，不代表默认公开 API 动作集合已经变化。

## 当前动作规则

- 猫默认生成 `eating`、`grooming`。
- 狗默认生成 `eating`、`standing`；`standing` 同时映射到兼容字段 `grooming`。
- 测试平台显式选择小型犬时可测试 `eating / drinking / running / sleeping / toileting / standing`。
- 中型犬测试路径仍以 `eating / standing` 为主。

## 关键不变量

- 每个动作固定完成 `5` 轮 Qwen 候选生成，不因前序候选合格而提前停止；随后从通过身份底线的生成候选中选择综合罚分最低者。
- 原始上传图只用于建立身份、身份审计和必要的身份回绘佐证，不作为生成失败时的最终降级输出。
- 上传动作候选如果未通过颜色/条纹身份审计，重试耗尽后也不能重新放行。
- 后续候选必须读取上一轮实际身份门问题；原图有可测浅条纹而候选仅放大该花纹时，可把姿态安全候选作为零身份权威的精修几何底稿，原图无条纹证据时仍禁止。
- 条纹身份门按源图证据分层：无条纹源图沿用严格“新增条纹”阈值；存在至少 `1` 个、面积不少于 `0.3%` 的真实条纹组件时，只阻断同时新增至少 `6` 个组件、`5.0%` 条纹面积和 `6.5%` 暗部对比度的严重放大。
- 吃饭主裁剪漏检源条纹时，只能由已通过的上半身裁剪提供源条纹交叉证据；主裁剪相对该证据达到严重放大阈值时仍失败关闭。
- 吃饭身份精修可从前 4 轮捕获动作/食盆安全且仅有条件性身份漂移的几何源；第 4 轮首次严格接触时，第 5 轮继承该几何回绘身份。
- 吃饭首帧接触先使用严格 SCAIL 道具分割；暖色毛发与棕色食物相连导致严格分割失败时，只允许独立的“宽中性食盆 + 紧凑中性口鼻间距”佐证动作接触，且不得放宽或改写下游宠物/道具遮罩。
- 犬类吃饭动作中，白膜只提供受控动作几何或时间曲线，不能覆盖耳形、口吻、体型和尾形。
- 根目录 Python 文件主要是兼容入口；新实现优先放在 `src/comfy_pet_pipeline/`。

## 质量与失败策略

- 运行完整性失败会阻断任务。
- canonical 内部洞门禁要求缺口组件至少有 `12%` 面积进入主体中线走廊；仅擦到中线边缘的肩、腰、臀侧轮廓凹陷只记录审计，不再误判为主体穿孔。
- canonical 语义降级抠图在接受前执行同一内部洞门禁；生成 canonical 抠图确实无效时，可用上传身份安全抠图继续建立 canonical，但上传原图仍不能成为动作首帧、SCAIL 动作参考或最终输出。
- 细粒度视觉质量审核以 advisory 记录为主，除明确身份底线外不应被旧策略误杀。
- e2e 脚本可能调用 GPU 和完整生成链路，不进入默认 pytest 集合。

## 回归稳定性合同

- 每次仓库修改统一运行 `bash ops/scripts/verify-change.sh`，覆盖默认 pytest、流水线导入、历史语料 SHA 和 6 组 canary 输入合同。
- 历史质量样例只记录 `MATCH/DRIFT` 诊断，画面质量变化不阻断；稳定性验收不读取身份、姿态、毛发或接触质量字段。
- 影响提示词、工作流、模型调用、队列/状态、输出发布或 GPU 生成的服务修改，在安全重启后运行 live smoke：一组重复三视图猫 `grooming` 和一组户外金毛犬 `standing`，串行提交。
- live 成功只要求新任务终态为 `completed`、每个请求动作有主动画、主动画可下载且媒体格式可读；动作专属修改可显式选择其他历史案例，但只有现行代码完成性稳定的输入进入必跑 smoke。
- live 图集发现已有 `queued/running` 任务时默认拒绝提交，避免与单卡在线任务争用。
- 历史媒体按 SHA 固化在 `/data/comfy-pet-pipeline/archive/regression-gallery/`，Git 和知识文件只保存非敏感来源元数据与合同。

## 数据与部署边界

- 敏感配置位于 `/etc/comfy-pet-pipeline/`，仓库只保留示例。
- 模型、任务产物、Profile 运行资产和验证归档位于 `/data/comfy-pet-pipeline/`。
- ComfyUI 生产运行代码位于 `/opt/comfyui/current`；仓库中的 `ComfyUI` 是兼容入口。
- systemd、Nginx 和环境模板位于 `ops/`。
