# Comfy Pet Pipeline 当前知识

## 目标

上传一张必选宠物正面图和最多两张侧面图，先确定猫/狗物种并生成 canonical 身份参考，再生成相应动作 GIF/视频，同时尽量保持毛色、花纹、耳形、口吻、体型和尾形身份一致。

## 当前对外能力

- 简化 GIF API：端口 `8051`，同一 `/api` 端点使用 `type=upload` 提交、`type=query` 查询。
- 本地视频 API：端口 `8770`，路径 `/api/local-video`；公开入口为 `https://ai.hzzootech.com/api/local-video`，裸 IP 的 HTTP 默认站点按 Nginx 安全策略返回 `404`。
- ComfyUI：端口 `8188`，承担底层工作流执行。
- 测试平台：用于显式测试犬型及扩展动作，不代表默认公开 API 动作集合已经变化。

## 内容审核与交付边界（v2.27.0）

- 独立 Content Review 的现有统一接口接入 Comfy；现有 `/pet-generation/history` 增加审核状态、原始输入/结果的鉴权预览、审核记录/生效规则导出、人工通过/驳回及显式重审。平台绑定既有账号，独立复核密钥仅存在服务器。
- 新任务按配置持久化审核要求。输入在生成前审核：拒绝停止，待复核和异常暂停。生成完成即开放下载并发送成功回调，结果审核与人工复核异步进行，二者不阻塞首次交付。
- 机器结果拒绝或人工驳回拦截后续下载及尚未发送的成功回调；已下载/已发回调/客户端缓存无法追回。降级恢复、服务重启、过期人工决定不能绕过拒绝。内部生成仍能读取中间结果，不能使用对外隐藏后的输出清单生成 canonical。
- 结果审核有独立队列和每任务锁，重启恢复未完成审核；结果重审不重新生成，曾拒绝的结果重审时仍撤销交付。文件 SHA、本地策略版本、上游实际策略/模型状态、trace 和决定事件留在私有任务记录，不写图谱。旧任务无记录明确“未审核”，测试复核明确 `automated_test / verification_review`，不能充当真实人工复核证明。
- 2026-09-30 上游实时健康显示图片仅肤色启发式、PaddleOCR 和文字审核可用，NSFW/NudeNet/vision safety 关闭，视频 1 FPS、最多 60 帧、ASR 关闭；GIF/APNG 转 MP4 后采样不是逐帧。完整运行阈值未由现有 API 暴露；少量接口样例/控制逻辑测试不代表全面违法内容准确率或交付前审查证明。
- 依据：`docs/api/CONTENT_MODERATION.md`、`docs/knowledge/DECISIONS/0016-content-moderation-async-delivery.md`。启用情况以部署环境和运行规则导出为准，不能由代码存在推断已上线。

## 当前动作规则

- 猫默认生成 `eating`、`grooming`。
- 狗默认生成 `eating`、`standing`；`standing` 同时映射到兼容字段 `grooming`。
- 测试平台显式选择小型犬时可测试 `eating / drinking / running / sleeping / toileting / standing`。
- 中型犬测试路径仍以 `eating / standing` 为主。

- 猫舔毛导出使用 `grooming_forward_natural_cycle_v2`：完整正向源视频优先；接缝不合格时搜索 `0.5–3` 秒、`0.85–1.15×` 速度的连续自然周期。实际透明主体的头部/抬爪运动幅度、边界方向以及视频/动画全部循环接缝共同选优。GIF/APNG/白底 MP4 共用源窗口与重复次数；禁止回文倒序、RGB 混合和静态替代。无合格周期时保留完整正向动作并记录 `forward_with_seam_warning`；顺序完整性硬校验，视觉接缝不单独阻断。原模型视频另存 `grooming_subject_replacement_source.mp4` 并记录 SHA-256。

- 默认猫狗任务按 `species:action` 建立不可变执行作用域：猫为 `cat:eating / cat:grooming`，狗为 `dog:eating / dog:standing`。请求顺序索引与实际执行顺序分离，禁止再靠交换姿态顺序规避前序失败。
- Qwen 动作首帧、上传动作导图配置和 SCAIL 动画阶段都为当前动作深拷贝有效配置，只暴露该动作的配置切片；一个动作的临时改写、失败状态、计时或恢复元数据不得被兄弟动作复用。
- 单动作普通异常先记录到该 `species:action:stage`，清理 ComfyUI 后继续执行同任务的兄弟动作；所有兄弟动作都尝试完成后再聚合失败并进入既有逐动作终态恢复。用户取消仍立即传播，不受隔离屏障吞掉。
- canonical 是两个动作共享的身份锚点，不能采用“媒体完整但身份已漂移”的生成候选。低饱和灰黑/暖棕混合被毛会阻断高饱和橘化、源图不存在的头部红粉特征和严重条纹放大；最后一轮以上传主体安全抠图、`denoise=0.70`、至少 `8` 步且无用户 LoRA 轻重绘，三轮仍全部身份不安全时改用上传身份安全抠图作为 canonical。
- canonical 的上传身份安全抠图例外只向后续动作提供身份，不是动作生成结果。猫狗每个动作仍必须从自身五轮 Qwen 真实生成候选中选择，上传图、canonical 或兄弟动作不得替代动作首帧、SCAIL 参考或最终动画。
- 每个动作固定完成 `5` 轮 Qwen 候选生成，不因前序候选合格而提前停止；优先选择严格合格候选，严格候选为空时从媒体完整的生成候选中选择最低风险者并标记 `best_effort`。
- 固定五轮预算禁用历史首帧缓存读取；缓存只允许写入审计，不能替代、增加或跳过本次任务的五次真实生成。
- 原始上传图只用于建立身份、身份审计、必要的身份回绘佐证和 canonical 身份安全抠图兜底；不作为动作候选、SCAIL 动作参考或最终降级动画。
- 颜色、条纹、动作、毛面、构图、背景和透明视觉审核继续指导重试与排序，但固定预算耗尽后不得单独导致任务失败。
- 犬类 canonical、动作首帧和 SCAIL 必须保持 photoreal 活体犬、连续细毛束、发丝自阴影与有机圆润解剖；暖色盘提示只约束色素，禁止用百分比或分区配额描述犬体，并明确排除 stylized 3D、cartoon、CGI、塑料、低多边形切面、平涂面板、几何化毛色分割、折纸、体素和纸模风格。
- canonical-first 犬动作的 Qwen 首帧只加载 approved photoreal canonical Image 1，文字动作是首帧姿态权威；白膜/轮廓动作导图不得作为 Qwen Image 2 或外观条件，只保留给 SCAIL 的逐帧几何和时序。仍使用四步 Lightning、固定五轮、原动作/身份门和选中后的非阻断暖色 LAB 恢复。
- 猫舔毛 Qwen 首帧固定以 canonical 作为 Image 1 唯一身份/外观权威，以去外观单色动作导图作为 Image 2 几何权威；允许全画布重绘，不能把 canonical 原始横卧姿态或导图灰模外观当作身份约束。
- 猫舔毛首帧先执行保持宽高比的全身姿态注册，再执行局部抬爪、嘴部接触和外观审核；SCAIL 输出用首、中、末三帧审计参考身份相对灰模 driver 的保持情况，最多三轮降低姿态强度重试，耗尽后选择最低身份罚分的真实生成视频继续。
- 猫舔毛使用公开单色导图的绿色内部开通通道作为“抬起前肢与躯干分离”的拓扑佐证；低频边界覆盖、平均距离和方向一致性参与五轮候选排序，但只记录 advisory 诊断，不得改变任务的完成/失败结果。
- 猫舔毛第 4、5 轮为解剖优先自由重绘：允许调整头、肩、关节、比例、取景和次要花纹，以清晰的肩—肘—腕—爪链路和恰好四条连接身体的腿优先；仍只生成固定 5 轮，不读取历史缓存，不追加第 6 轮。
- 后续候选必须读取上一轮实际身份门问题；原图有可测浅条纹而候选仅放大该花纹时，可把姿态安全候选作为零身份权威的精修几何底稿，原图无条纹证据时仍禁止。
- 条纹身份门按源图证据分层：无条纹源图沿用严格“新增条纹”阈值；存在至少 `1` 个、面积不少于 `0.3%` 的真实条纹组件时，不再套用无条纹源图的 `1.8%` 面积上限，只阻断同时新增至少 `6` 个组件、`5.0%` 条纹面积和 `6.5%` 暗部对比度的严重放大。
- 吃饭主裁剪漏检源条纹时，只能由已通过的上半身裁剪提供源条纹交叉证据；主裁剪相对该证据达到严重放大阈值时仍失败关闭。
- 吃饭身份精修可从前 4 轮捕获动作/食盆安全且仅有条件性身份漂移的几何源；第 4 轮首次严格接触时，第 5 轮继承该几何回绘身份。
- 浅色消色差犬的吃饭候选若只因暗斑大幅扩张失败，可在原五轮候选内对正式宠物/食盆分割确认的中性毛色做分区 LAB-L 恢复；食盆、alpha、非宠物像素和彩色宠物细节必须逐像素锁定，恢复后重新通过原身份与姿态门，不能增加第六轮或放宽身份阈值。
- 暖色犬 canonical 若仅把连续金色/姜黄/橘色底毛迁移为白灰区域，可使用源图 LAB 分布重建候选的连续暖色分布；不得复制源图空间像素或改变候选 alpha、姿态和几何，且必须重跑原身份门。提示必须禁止把浅色高光扩张为白斑、花斑或另一白斑犬种。
- 暖色犬动作五轮选优后若选中生成候选仍只含“新造离散白斑/暖色转消色差”问题，可在不调用模型的前提下用 approved canonical 的 LAB 分布修正宠物中性区域；吃饭必须先用正式身份/食盆分割锁定完整道具。修正不得改 alpha、姿态或复制 canonical 空间像素；失败、无改善或姿态复验回退时只跳过，不能阻断完成。
- 吃饭首帧接触先使用严格 SCAIL 道具分割；暖色毛发与棕色食物相连导致严格分割失败时，只允许独立的“宽中性食盆 + 紧凑中性口鼻间距”佐证动作接触，且不得放宽或改写下游宠物/道具遮罩。
- 犬类吃饭动作中，白膜只提供受控动作几何或时间曲线，不能覆盖耳形、口吻、体型和尾形。
- 犬吃饭选中参考缺少口鼻锚点，或参考食盆语义框宽高比低于 `1.40`、说明食盆分割已吞进口鼻时，必须以选中 Qwen 图作身份权威、摘要锁定白膜作完整 81 帧身体/食盆动作权威；不得裁掉被遮住且无法从单张低头参考恢复的下口鼻，也禁止静态姿态兜底。极端下游降级 GIF 仍必须做局部头颈低—高—低动作，食盆和下半身固定。
- 吃饭 SCAIL 输出除全帧邻帧能量和首帧 excursion 外，还必须通过动作来源对应的局部门。参考空间头部形变追踪中央暗色口鼻组件，稳健纵向跨度至少 `8 px`，并至少保留准备动作头部抬升的 `25%`（上限 `18 px`）；完整白膜驱动用逐帧身份框最高头部范围和静态食盆定义整段低—高—低走廊，要求相对首帧 MAE P90 至少 `28`，且像素差不小于 `20` 的变化面积 P90 至少 `40%`。不得用食盆上方固定窗口、全图噪声、身体抖动或食盆阴影冒充口鼻动作；失败进入最多五轮增强姿态信号的真实 SCAIL 重试并按局部最弱动作轴选优。
- 吃饭透明输出把食盆标记为静态道具，但宽泛红色引导区不能直接强制不透明。每帧优先使用有界画布 alpha；画布不均匀时改用跨帧 U2Net/chroma alpha，二者都只接受支持不少于引导区 `55%` 的可靠食盆证据。至少 `25%` 帧可靠后，以多数支持和最高支持代表帧构建时序食盆 RGB/alpha，只在证据包络内补回缺失帧。边缘清理必须保护该核心，最终高 alpha 保留率不低于 `97%`；没有任一 alpha 证据的引导外扩保持透明。drinking 仍要求有界均匀画布。
- 站立透明输出使用姿态引导的自适应画布 matte；浅色脸、身体和腿由有界画布结果补回。只填充外部画布不可达且与侵蚀姿态核心重合的封闭内部洞，自然腿间/尾部间隙保持透明，边缘清理失败逐帧回滚。
- 根目录 Python 文件主要是兼容入口；新实现优先放在 `src/comfy_pet_pipeline/`。

## 质量与失败策略

- `v2.26.65` 原任务 `20260905T083916Z-0124acd4b4` 离线修复选出连续源帧 `67–78`，正向重复 `6` 次、动画速度 `0.9×`。100 帧 APNG 全部逐字节匹配对应源 matte，81 帧白底 MP4 全部匹配正向源映射，GIF 首尾/相邻差异比 `1.360783` 通过接缝检查。旧策略的 `40→80→40` 倒放被移除；此离线证据不代替 mandatory live smoke。

- 运行完整性失败会阻断任务。
- canonical 内部洞门禁要求缺口组件至少有 `12%` 面积进入主体中线走廊；仅擦到中线边缘的肩、腰、臀侧轮廓凹陷只记录审计，不再误判为主体穿孔。
- canonical 先执行严格内部洞、透明和身份审核。只有至少一个生成候选通过身份门时，严格抠图耗尽才可对该身份安全生成图执行不阻断视觉门的语义抠图；所有生成候选身份不安全时必须切换为上传身份安全抠图，不能用完成优先继续传播错误身份。
- 细粒度视觉质量审核均保留为重试、排序和 advisory 审计；视觉问题不能在固定预算耗尽后阻断。模型/进程无输出、媒体不可读取、主体 alpha 不可用、摘要变化和主产物缺失仍失败关闭。
- e2e 脚本可能调用 GPU 和完整生成链路，不进入默认 pytest 集合。

## 回归稳定性合同
