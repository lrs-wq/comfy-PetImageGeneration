# 0001：五轮生成候选与最优结果选择

- 状态：accepted
- 日期：2026-08-31
- 负责人：项目负责人
- 影响节点：`comfy.module.pipeline`、`comfy.module.identity`、`comfy.module.quality`

## 背景

首版知识图谱曾将失败策略记录为“终端降级回原始上传图”。这不符合当前正式策略：系统应在有限生成预算内产生多个候选，并在生成结果中取最优。

## 决策

- 每个动作固定完成 `5` 轮 Qwen 候选生成，不因前序候选合格而提前停止。
- 在通过身份底线的生成候选中，按身份保持、动作正确性和视觉质量选择综合最优结果。
- 原始上传图可用于建立身份、身份审计和必要的身份回绘佐证，但不能作为五轮生成失败后的最终降级输出。
- 未通过颜色、条纹等身份底线的候选，不因生成预算耗尽而重新放行。
- 条纹底线必须区分“无条纹源图新增花纹”和“有真实浅条纹源图的风格化放大”：前者沿用严格阈值，后者仅在组件数、占用面积和暗部对比度三项同时达到严重放大阈值时阻断；这属于源证据分类，不是预算耗尽后的豁免。
- 下一轮可读取上一轮的身份问题并在五轮预算内定向纠正；被拒候选只能在已有独立证据证明动作几何安全且其身份问题可由原始身份证据回绘时作为零身份权威的几何底稿，最终输出仍须重新通过身份底线。
- 第 4 轮仍属于可捕获的几何底稿：如果它是首次严格通过动作/道具几何、但仅有可修复身份漂移的候选，第 5 轮必须优先继承该几何做身份回绘，不能因“精修从第 4 轮开始”而遗漏它。
- 吃饭首帧的 SCAIL 严格道具分割若因暖色宠物与棕色食物相连而失败，可由不产出遮罩的独立中性食盆—口鼻间距门佐证；中性口鼻缺失或高估间距时，可在同一已定位食盆中心窄走廊中用高饱和鼻端—暖色食物的横向密度再次佐证。两条只读路径都只参与五轮候选判定，保持 `0–8 px`，不得修改下游身份/道具分割阈值。
- 前序吃饭候选若身份、透明完整性和轮廓均合格且唯一问题是口鼻离碗，可在第 4/5 轮选择实测间隙最小者做局部接触修复；只开放头颈—口鼻—碗口走廊，canonical 仅佐证身份，白膜仅佐证动作几何。后一轮可使用更新后的更近候选，已有严格合格候选时不得回退，且不得增加第六轮或放宽接触/遮罩门。
- 语义抠图是五轮内候选的后处理，不计作第六个生成候选；下游恢复只能复用已经选定的生成候选。

## 备选方案

- 失败后直接返回原始上传图：未采用，因为这不是动作生成结果。
- 预算耗尽后选择身份审计失败的候选：未采用，因为会破坏宠物身份一致性。

## 后果

- 最坏情况需要承担五轮生成的 GPU 时间和等待时间。
- 候选记录必须保留轮次、身份审计、动作门禁、质量分数和最终选择原因。
- 五轮全无身份合格候选时，末态必须记录完整的 `5/5` 尝试数、未发布和身份问题计数；不得先写入“已接受最佳降级”再失败。
- 异常恢复必须校验逐动作五轮选择记录与所选候选摘要，旧任务中的原图或 canonical 派生文件不能凭文件名重新获得输出资格。
- 文档和 Agent 不得再将“降级回原图”描述为当前策略。
- `v2.26.40` 已在 `v2.26.39` 生产基线上按本决策修改实现、恢复边界、健康接口、测试和现行文档；历史版本说明继续保留当时行为，仅用于追溯。
