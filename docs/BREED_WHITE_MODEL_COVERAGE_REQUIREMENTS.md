# 常见猫狗品种白模覆盖要求

> 文档版本：1.0  
> 日期：2026-08-21  
> 状态：待实施  
> 适用项目：`comfy-pet-pipeline`

## 1. 背景与目标

当前主体替换链路只有一个基础白模，无法稳定覆盖不同猫狗品种在头骨、吻部、耳型、躯干比例、腿长、尾型和毛量轮廓上的差异。单一白模会造成：

- 小型长毛犬被生成为中大型短毛犬；
- 短鼻、短腿或长身品种发生脸型和身体比例漂移；
- 动作阶段继承错误品种轮廓，即使颜色门禁通过也无法恢复真实身份；
- 衣服、眼镜和其他配饰被误判为毛色或天然条纹；
- 吃饭动作中的头部高度、吻部长度和食盆接触关系不适合所有品种。

本需求的目标是：

1. 覆盖中国宠物市场中的主要猫狗品种，并兼顾海外常见品种；
2. 以“形态白模簇”覆盖多个相近品种，不为每个颜色或花纹重复制作白模；
3. 根据上传图选择最接近的白模簇，只使用白模的动作和几何，不继承白模身份；
4. 保证毛色、花纹、脸、毛长和配饰始终以原始上传图为准；
5. 所有动作最终必须返回生成结果，候选不合格时重试，预算耗尽后返回身份风险最低的生成候选，不退回静态原图。

## 2. 市场覆盖依据

中国市场应优先覆盖中华田园猫、中华田园犬、布偶、英短、贵宾/泰迪和柯基等高占比类型。艾瑞 2026 年调研中，养猫人群前三为中华田园猫、布偶和英国短毛猫；养狗人群前三为中华田园犬、贵宾犬/泰迪和柯基犬。

同时参考海外登记数据补充法斗、拉布拉多、金毛、德牧、腊肠、比格和缅因等高频品种。

| 白模 ID | 覆盖范围 | 必须锁定的几何特征 |
| --- | --- | --- |
| `dog_toy_fluffy` | 泰迪、比熊、马尔济斯、西施、雪纳瑞 | 小体型、圆或方头、垂耳、较高毛量 |
| `dog_small_spitz` | 博美、吉娃娃、蝴蝶犬 | 小体型、尖嘴、立耳、卷尾 |

| `dog_retriever_standard` | 金毛、拉布拉多、田园犬和常见混血犬 | 标准长吻、垂耳、中大型躯干 |
| `dog_shepherd_athletic` | 边牧、德牧、马犬、澳牧 | 长吻、运动型胸腰比例、较长腿 |
| `dog_short_leg` | 柯基、腊肠 | 短腿；必须提供柯基和腊肠两套躯干长度参数 |
| `dog_brachycephalic` | 法斗、巴哥、英斗、波士顿梗 | 短鼻、宽头、紧凑胸腔 |

| `cat_cobby_round` | 英短、折耳、异短 | 圆头、粗壮、短颈、紧凑体型 |
| `cat_longhair` | 布偶、英长 | 中大型长毛、长尾、自然毛量轮廓 |
| `cat_large_longhair` | 缅因、挪威森林 | 大体型、长身、大耳、长毛大尾 |

以下形态在统一白模中无法通过参数稳定表达时，必须拆分为独立白模：

- 腊肠犬的极长躯干；
- 波斯/异短的扁脸；
- 缅因猫的大体型和长方吻部；
- 无毛猫的无毛轮廓；
- 巨型犬和灵缇类的极端体型。

## 5. 不得重复建设白模的外观变化

下列差异属于身份外观，不属于白模几何，不得为其单独制作白模：

- 英短蓝猫、蓝白、金渐层、银渐层；
- 田园猫的狸花、橘、三花、奶牛、纯白和纯黑；
- 美短虎斑、加白及其他花色；
- 布偶的双色、重点色和手套色；
- 同一品种的颜色、斑点、条纹、眼睛颜色；
- 衣服、项圈、胸背、眼镜、发饰及其他配饰。

这些信息必须由原始上传图、身份分割、毛色空间检测和身份提示词控制。

## 6. 白模资产要求

### 6.1 几何要求

每个白模必须表达并记录：

- 物种：`cat` 或 `dog`；
- 白模簇 ID 与版本；
- 头宽、吻部长度和鼻口高度；
- 耳型：立耳、半立耳、垂耳或折耳；
- 躯干长宽比；
- 腿长与身体高度比例；
- 胸腔、腰部和臀部比例；
- 尾巴长度、粗细和卷曲类型；
- 基础毛量轮廓：无毛、短毛、中长毛、长毛、高蓬松；
- 食盆相对前爪、嘴部和身体的位置。

白模不得携带具体品种毛色、条纹、斑点、眼色、服装、配饰或环境纹理。

### 6.2 动作要求

每个投入生产的白模簇至少必须具备：

1. `eating`：嘴部真正进入食物区域，食盆不遮挡或替代四肢；
2. `standing`：完整四肢连接、稳定站立、头尾完整；
3. 当前产品开放的其他动作，例如 `grooming`，必须按同一白模簇补齐。

驱动视频应保持当前生产规格：

- 512×512；
- 81 帧；
- 16 FPS 生成时间轴；
- 纯动作、道具和相机几何；
- 不携带可被 Qwen 当作身份的颜色、毛发纹理或脸部明暗。

### 6.3 Qwen 几何引导要求

吃饭 Image 2 几何引导必须：

- 使用纯绿色背景；
- 宠物主体使用单一中性灰，例如 RGB `[132, 132, 132]`；
- 主体内部不得存在源视频明暗、眼睛、鼻子、嘴、毛发或品种纹理；
- 食盆、盆沿和食物使用固定语义色；
- 保存主体、食盆、食物像素数量和接触关系元数据；
- 校验主体颜色唯一、无高频纹理、无源 RGB 和源亮度残留。

## 7. 白模路由要求

### 7.1 路由输出

上传图片后，路由器至少返回：

```json
{
  "species": "dog",
  "morphology_cluster": "dog_small_spitz",
  "confidence": 0.91,
  "alternatives": [
    {"cluster": "dog_toy_fluffy", "score": 0.42}
  ],
  "evidence": {
    "muzzle": "short_pointed",
    "ears": "upright",
    "leg_ratio": "normal",
    "coat_volume": "high"
  }
}
```

系统不要求准确识别纯种名称，但必须选择正确的形态簇。混血宠物应按几何最近邻路由，不得强行贴纯种标签。

### 7.2 降级策略

- 犬类无法判定时降级到 `dog_retriever_standard`，但必须记录低置信度；
- 猫类无法判定时降级到 `cat_standard_shorthair`，但必须记录低置信度；
- 短鼻、短腿、长身和巨型轮廓属于强特征，不得降级到标准体型；
- 三视图重复或近似重复时降级为单视图，不重复计算身份证据；
- 路由结果、置信度、输入摘要和最终白模版本必须写入任务状态。

## 8. 身份、服装和配饰隔离要求

本节为强制要求，来源于任务 `20260821T075838Z-0e6161264e` 的实际失败：原图中的黑白条纹衣服被错误识别为宠物天然黑色花纹，导致白色博美被生成成黑斑短毛狗。

必须实现以下隔离：

1. 毛色和条纹审计只能统计真实毛发区域；
2. 衣服、胸背、项圈、眼镜、食盆和背景不得进入毛色签名；
3. 无法可靠区分服装时，条纹证据标记为 `unavailable`，不得作为“原图已有条纹”的放行依据；
4. canonical 和动作候选都必须分别执行“新增斑点/条纹”空间检测；
5. 白色或浅色宠物出现大面积黑斑、虎斑或斑点时必须拒绝并重试；
6. 配饰是否保留应由独立产品策略控制，不得转化成宠物毛色；
7. 动作颜色始终锚定原始上传图的毛发区域，不锚定白模、canonical 或服装区域。

## 9. 候选门禁与任务完成要求

每个 canonical 和动作候选必须检查：

- 主体完整性和画布边距；
- 动作姿势与道具关系；
- 原始上传图锚定的毛色分布；
- 暖色流失与灰黑扩张双向漂移；
- 新增条纹、斑点和大面积色块；
- 毛长、毛量和外轮廓；
- 与 canonical 及其他动作的重复度；
- 背景、Alpha 和绿幕污染。

处理策略：

1. 不合格候选不得立即进入 SCAIL；
2. 必须使用完整候选重试预算；
3. 吃饭候选若仅有 `eating_bowl_contact_unreliable`，可作为第 5 次身份修复的几何来源，但不能直接视为严格通过；
4. 身份修复必须使用动作候选、canonical 和原始上传前视图三路输入；
5. 全部候选耗尽后，选择身份风险最低且仍为生成结果的候选继续；
6. 不得用原始上传静态图伪装成动作输出；
7. 最终任务必须返回结果，并在状态中明确标记严格通过或降级候选。

## 10. 验收标准

### 10.1 单白模验收

- 白模物种和形态簇与配置一致；
- 四肢、尾巴、耳朵和吻部完整，无断裂、融合或替代；
- 吃饭动作中嘴部与食物有真实接触或重叠；
- 几何引导主体为唯一中性灰，不含身份细节；
- 驱动视频和元数据摘要固定且可重现；
- 同一白模能够覆盖表中列出的相近品种，不产生明显比例错误。

### 10.2 上传身份验收

- 至少使用每个 P0 品种 10 张不同个体图片测试；
- 浅色、深色、纯色、天然条纹和天然斑点分别覆盖；
- 至少 20% 测试图包含衣服、项圈、胸背或眼镜；
- 服装花纹不得转化为毛发花纹；
- 毛色、花纹、毛长、脸型和耳型必须与上传主体一致；
- 每个动作记录白模簇、候选审计、重试次数、修复来源和最终选择原因。

### 10.3 发布门槛

- P0 品种整体任务完成率必须达到 100%；
- 严格候选通过率应单独统计，不得与降级完成率混合；
- 不允许出现“任务完成但结果退回原始静态图”；
- 新增斑点、条纹或跨品种体型漂移必须为零容忍发布问题；
- 服务健康接口必须暴露白模簇版本、可用动作、资产摘要和路由状态。

## 11. 实施优先级

### 第一阶段：P0

1. 建设 8 个犬类和 6 个猫类基础形态簇；
2. 优先完成 `eating` 和 `standing`；
3. 增加形态簇路由器；
4. 增加服装/配饰与毛发区域隔离；
5. 为所有白模生成无身份细节的平面几何引导；
6. 建立按品种和形态簇统计的回归测试集。

### 第二阶段：P1

1. 拆分腊肠、扁脸猫、巨型犬和灵缇等极端形态；
2. 补齐 `grooming` 等其他开放动作；
3. 支持多视图联合形态判断；
4. 对混血宠物支持连续比例参数或两个白模簇之间的受控插值。

## 13. 运行时动作几何合同（API 2.26.35）

犬类喝水的唯一高质量几何策略是 `full_white_driver_drinking_pose_static_bowl_v2`。上传身份参考只作为 SCAIL 身份权威；接近水碗、低头接触、饮水、抬头返回、身体/四肢变化和场景道具必须来自摘要绑定的完整动态白膜。系统逐帧保留白膜主体轮廓，以至少 60% 帧可检出的食盆为依据做 25% 时间投票，固定食盆遮罩和中值 RGB。旧的 `reference_space_white_driver_head_path_static_bowl_v3` 只移动局部头部并锁定身体，不得进入高质量 SCAIL 主链路。完整白膜处理失败时可以产出身份锚定降级结果，但静态或局部动作不得标记为高质量喝水结果。

喝水透明发布必须使用完整白膜遮罩的蓝色主体与红色静态水碗角色。犬只以语义抠图为主，水碗只在红色道具区的有界邻域内用均匀画布分割补回，禁止用画布分割替换整只犬的语义轮廓。每一帧水碗硬 Alpha 相对红色白膜道具遮罩的保留率必须不低于 `90%`；该专门门禁必须在循环闭合与 GIF/APNG 编码前通过，整体主体覆盖率不能代替水碗保留率。

GPU 提交前必须把准备后的 `tm_pose` 与原始白膜直接比较：首帧异或轮廓动作幅度至少保留 `70%`，编码后的红色水碗遮罩面积至少保留源白膜静态水碗的 `75%`。SCAIL 输出既要相对 `tm_pose` 保留至少 `35%` 的轮廓动作幅度，也要相对原始白膜直接保留至少 `65%`。只有纹理、舌头或亮度变化而身体轮廓基本静止时必须拒绝。两次重试的姿态强度分别提高到原值的 `1.18` 倍和 `1.32` 倍，仍不达标时只允许当前动作降级，不能发布为高质量结果。

喝水与吃饭透明循环不得对空间位置不同的首尾主体做 RGB/Alpha 交叉溶解。发布端只能在驱动已返回起始相位的末段执行终帧相位对齐，必须保持单一主体轮廓，禁止出现双重主体、半透明残影或大范围软 Alpha 重叠。

健康接口必须公开完整白膜主策略、旧局部头部策略不可高质量发布、GPU 前源白膜门禁和 SCAIL 后源白膜门禁。主链路与 8050 测试平台必须指向同一不可变发布目录，版本、提示词、驱动摘要和 OpenAPI 契约以该目录为唯一事实来源。

犬类如厕透明提取必须把参考遮罩中的蓝色犬只和红色托盘都纳入完整前景合同。犬只仍由语义/画布联合提取；已验证的静态红色托盘需要逐帧保留，低对比度托盘像素应做中性化去绿，不能因其颜色接近画布而消失。透明提取失败只能降级当前动作，后续兄弟动作必须继续执行。

猫/狗吃饭的 Qwen 几何图中，主体必须是单一 `RGB(132,132,132)` 的平滑轮廓；不得保留白膜或驱动视频的 RGB、色度、原始亮度值及低频明暗分区。头部降低、连续嘴部接触、食盆边缘和食物可以用固定语义色表达，但主体内部灰度层级不得承担解剖语义。带新增条纹、非黑白身份的明暗平衡漂移或暗色特征扩张的候选不得作为后续 identity-refine sampler。

动作配置按物种和动作分别冻结：猫为 `eating / grooming`，默认犬为 `eating / standing`，小型犬测试 Profile 为 `eating / drinking / running / sleeping / toileting / standing`。每个动作使用独立几何引导、提示词、seed 偏移、SCAIL 实验目录、质量记录和输出路径；任务内只共享上传身份 canonical 与串行 GPU 资源。单动作 Qwen 首帧重试耗尽时不得降级为原图、不得移除动作，也不得进入 SCAIL；必须使用新的 seed 波次重新排队，直至得到严格门禁通过的首帧或用户主动取消。同一上传视图、Profile、动作导图和策略摘要可以复用已验证首帧，但必须验证缓存 SHA，并在当前任务中重新执行动作、身份、色盘及透明边缘门禁。首帧已经通过后，SCAIL/透明输出质量失败仍按动作隔离并保留真实失败审计。canonical 建立失败、上传摘要失配、模型/存储/GPU 等基础设施故障仍属于任务级失败。
