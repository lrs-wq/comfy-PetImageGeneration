`v2.21.0` 接受两种上传集合：仅 `image`，或完整的 `image`（正面）+ `image_left`（左侧）+ `image_right`（右侧）。不接受只传一个侧面或缺少任一视角。三视角逐张规范化并锁定原始/规范化 SHA-256，在 GPU 前检查角色集合、文件完整性、完全或近重复视角、可用主体分割和明显毛色类别冲突。三张图仅接入 Qwen 全身 canonical 的 `image1/image2/image3`；动作 Qwen 不读取原始三视角，只读取归一化 canonical 与 Main_case 几何，并按动作分配 Image 1/Image 2 角色。

- `type=final_video_fur_surface_audit`：最终 MP4 的抽帧毛发表面报告，包含 Profile/Qwen/遮罩 SHA、逐帧双通道判定和失败关闭原因；
- `type=transparent_gif`：最终透明循环 GIF。

任务审计字段 `canonical_reference_generated=true`、`canonical_reference_used=true`、`generated_canonical_bypassed=false` 用于证明全身图没有被绕过。`pose_identity_input_policies` 应显示吃饭和舔毛均为 `canonical_character_image1`；实际工作流还应证明 Image 1/sampler/identity 均指向 canonical、Image 2 指向动作几何，并证明 Photography/身份 LoRA 没有被重新启用，LoRA 层只有核心 Qwen Lightning。

动作 Qwen 不复述冗长的 canonical 外观提示，而使用按动作分离的紧凑合同。吃饭和舔毛都由 Image 1 定义身份/风格，Image 2 只定义动作几何与动作必需道具；犬类吃饭、喝水、如厕会在专用动作提示后重新绑定上传色盘。每个候选（包括非纯绿候选）都独立选择 direct chroma 或 semantic matte，并只以自己的最终 512×512 RGBA 参加动作、canonical 身份比例、姿态和毛发表面审计。五轮全部完成后才选择：严格合格候选优先，否则发布最低风险且媒体完整的生成候选为 `best_effort`。选定文件只按字节复制为持久引用，Wan 绿底由该 RGBA 单向派生，不重做 chroma key；canonical 和原始上传图都不能替代动作输出。

吃饭接触门排序后最多保留 `12` 个候选组件的审计，字段包含 `bbox`、`area`、`gap_px`、`width_bowl_ratio`、`height_bowl_ratio`、`center_offset_bowl_ratio` 和 `rejection_reasons`。它检查最终 Qwen 动作候选中的口鼻是否已到达检测到的碗口；Main_case 几何引导内的 `6–10 px` 口鼻—食物重叠仍由独立几何校验负责，不能用本门替代。

## 旧版显式链路：`keyframe_video`

以下多姿态、Wan 2.2、GIF/APNG 说明只适用于显式提交 `generation_mode=keyframe_video` 的兼容接口，不描述默认主体替换生产链路。本节所有创建任务的 POST 都必须携带该字段；省略时会进入默认 `subject_replacement`，不会执行下述旧链路。

### 生成 512×512 无背景动画

传入 `output_format=transparent_gif` 后，接口会自动执行：

1. 读取上传照片中的毛色分布、脸型、眼睛、耳朵、鼻口、体型、毛长和尾巴等身份特征；默认基准会同时建立源图毛色调色板签名。
2. 生成一张“标准萌系 3D 身份图”，固定脸型、毛色、花纹、眼睛和渲染质感，同时明确禁止眼镜、项圈和服装。
3. 默认生成奔跑、吃饭、喝水、趴卧四张完整全身首帧；未知区域不臆造新花纹。吃饭和喝水只允许一个贴近前爪的浅碗。
4. 姿态生图阶段只继承已确认角色图中的身份、毛色调色板与渲染风格，不再拼接用户提示词里的坐姿、特写、镜头或构图要求；四个动作各自使用独立的首帧姿态模板。
5. 通过躯干纹理特征做内容级视觉跟踪，将主体核心区域固定到同一画布坐标；跟踪轨迹经过时域中值滤波并限制单帧补偿速度，避免舌头、腿或食盆运动触发整只猫跳动。不再做逐帧缩放，避免呼吸式缩放抖动。
6. 不使用第一帧覆盖、头部锁定或脸部像素冻结；头部、耳朵、脸、颈胸和四肢完整保留本地视频模型生成的原始动作。
7. 对透明蒙版做时域平滑、柔边和去绿边。
8. 输出 512×512、20fps、100 帧、5000ms、无限循环的 GIF 和 APNG。

```bash
curl -sS -X POST 'https://ai.hzzootech.com/api/local-video/jobs' \
  -H "X-API-Key: $API_KEY" \
  -F 'generation_mode=keyframe_video' \
  -F 'image=@/path/to/reference.jpg' \
  -F 'prompt=保留上传猫咪的全部身份特征，动作平滑，固定相机和主体位置' \
  -F 'output_format=transparent_gif' \
  -F 'seed=20260714'
```

不传 `poses` 时会按固定顺序生成 `running / eating / drinking / lying down` 四组结果，默认 `pose_count=4`。如需自定义，可继续传 JSON、换行或竖线分隔的 `poses`。

透明动画模式会自动加入身份保持、无服装萌系 3D 画风和脸部防扭曲约束，因此 `prompt` 只需描述整体要求，不需要重复猫咪外观或画风。系统通过躯干跟踪消除整体漂移；动作只由当前姿态的独立模板控制，只有吃饭和喝水允许一个贴近前爪的碗，奔跑和趴卧不允许任何道具。它会忽略普通视频的 `resolution` 参数，并强制最终输出为 512×512。任务完成后，`outputs` 包含：

- `type=cartoon_reference`：由上传照片直接转换的标准萌系 3D 身份图，所有姿态共用这套角色设计。
- `type=transparent_gif`、`primary=true`：兼容性版本，使用固定有序抖动模拟柔边。
- `type=transparent_apng`、`recommended_for_quality=true`：8 位柔和 Alpha，毛发边缘更自然，推荐支持 APNG 的客户端使用。
- `type=transparent_keyframe`：由上传照片生成、带完整 Alpha 通道的透明卡通 PNG 首帧。

GIF 格式本身只有 256 色和单级透明度，无法真正保存半透明边缘；APNG 才能保存柔和 Alpha。GIF 文件名为 `pose_01_transparent_512.gif`，高质量 APNG 文件名为 `pose_01_transparent_512_soft.png`。

#### 姿态重复保护与 LoRA 限幅（API 2.13）

为避免多个勾选动作最终生成同一张坐姿图，姿态阶段默认执行以下系统规则，用户不需要修改提示词：

1. 用户提示词只参与标准卡通身份图和视频动作方向，不直接进入四张姿态首帧的姿态、镜头、裁切与道具控制。
2. 标准身份图的用户 LoRA 总强度上限为 `1.0`；姿态首帧三次尝试的总强度上限依次为 `0.40 / 0.25 / 0.15`，同时保持多个 LoRA 原有的相对比例。
3. 普通姿态最多生成三次；奔跑首帧额外增加一次 10 步、独立 seed 的四爪落地专项重试。后续尝试会提高 Qwen 步数、减小 LoRA 姿态锁定影响，并加入明确的纠姿指令。
4. 每张候选图都会与标准身份图及前序已接受姿态比较归一化轮廓 IoU 和感知哈希；相同主体仅平移、缩放或轻微重绘不能绕过检测。
5. 如果无法提取候选主体或参考主体的相似度签名，任务按失败关闭处理，不会把空白图或无法判断的图当作合格姿态。
6. 图片任务的抠图失败会先重试；若最终存在姿态明确且不重复的原图，则返回该原图。纯姿态重复不会交给 rembg“恢复”，因为背景移除无法修正身体姿态。
7. 视频任务仍要求所有首帧能可靠抠图；不合格时正常报错，不会用不透明原图继续生成透明视频。

任务状态中的 `effective_canonical_settings` 和 `effective_pose_lora_attempts` 保存最终实际采用的 LoRA、融合模式、步数、CFG、重绘强度和相似度检查结果。历史页展示的是这些最终选中参数，而不是被拒绝尝试或仅有请求值。

#### 默认四姿态统一基准、毛色保护与中文翻译（API 2.18）

`request_kind=image` 和 `request_kind=video` 默认都启用 `pet-multipose-20260717-v2`，修订号为 `multipose-v2`。这是奔跑、吃饭、喝水、趴卧共同使用的图片与视频首帧统一基准，不是进食专用基准。它以历史任务 `20260717T094459Z-f738613526` 作为 LoRA、采样参数和渲染风格来源；该任务原有的“进食”内容只保留在 `eating` 动作层，不会进入公共基准。

基准采用两层提示词设计：

1. 公共基准层只定义身份、风格、完整全身构图和纯绿背景：`以参考图片中的猫咪为唯一身份标准，完整保留毛色和花纹位置、脸型、眼睛颜色与间距、耳形、鼻色、毛长、体型比例和尾巴特征；生成高品质萌系3D卡通角色，毛发细腻柔软，光照明亮柔和，保持自然无衣服无配饰的完整全身形象。不继承或固定参考图中的姿态、肢体坐标和构图，具体动作只由所选姿态决定。`
2. 动作层由 `running / eating / drinking / lying_down` 四个独立模板分别定义身体姿态、镜头、肢体接触关系、允许的道具和视频运动。公共层不包含俯身、低头、进食、碗或其他动作语义。

四个动作的边界如下：

- `running`：三分之四侧面、三爪贴近同一基线、一只近侧前爪轻抬；四肢分离，不腾空，不使用道具。
- `eating`：自然低伏俯身，口鼻接近唯一一个浅猫粮碗；两只前爪自然落地，禁止抬爪抓取、拿起或把食物送到嘴边。碗靠近前爪，但必须以一条可见的纯绿色窄缝与前爪分开，不能接触、遮挡或替代肢体。
- `drinking`：自然低伏俯身，唯一一个浅水碗靠近前爪，但必须以一条可见的纯绿色窄缝与前爪分开；只允许短小实心粉色舌尖接触水面，不能拉长或悬空。
- `lying_down`：完整狮身式趴卧，胸腹贴近基线，前爪平行前伸，尾巴完整；不使用道具。

此外，统一基准保留以下固定参数：

- 固定姿态种子偏移：`+101 / +211 / +307 / +401`，使单独生成或组合生成时保持可复现且降低姿态趋同
- `宠物小猫 _ 写实摄影_v3.0.safetensors`：`0.50`
- `Qwen Image-Kitten Photography_QWEN-小猫摄影.safetensors`：`0.60`
- Qwen：`steps=6`、`cfg=1.0`、`denoise=1.0`
- 基准种子：`20260715`

`pet-multipose-20260717-v1` / `multipose-v1` 保留为不启用毛色调色板保护的历史兼容配置。历史 ID `20260717T094459Z-f738613526` 仍保留为 `eating-v1` 兼容配置，仅用于显式复现旧进食任务；新请求默认使用 v2，避免同一 ID 在新旧任务间产生不同语义。

v2 默认启用 `identity_palette_guard=true`，当前策略为 `source_palette_guard_v3`：

1. 从上传原图分割宠物主体并提取黑、白、灰、暖棕/橙等主要毛色比例，形成源图调色板签名。黑/灰/白按“深色身份纹路”与“灰或白的中性浅色被毛”比较：允许摄影阴影中的白毛在 3D 风格化后变亮，但不允许深色纹路消失或扩成新黑斑。
2. 把识别出的主毛色和源图中明确缺失的高风险颜色写入身份图与姿态图的动态提示词，要求先锁定毛色再改变画风或姿态。
3. 每轮候选图都会重新提取毛色签名并与参考签名比较；新增显著橙棕色、把黑白猫改成暖色猫等高置信度身份漂移会被硬拒绝，并继续使用降低 LoRA 影响的重试结果。鼻头和耳内等局部红粉皮肤色单独统计，不再误判成整片暖色被毛。
4. 吃饭和喝水先执行与其他姿态相同的完整主体毛色检查；若仅完整主体检查失败，再排除下部餐碗区域做一次上半身确认。只有上半身毛色保持时才把失败判为餐碗颜色污染并放行；上半身也漂色时仍然拒绝。奔跑和趴卧不做道具豁免。
5. 如果主体分割不足以建立可靠签名，调色板保护按“不可用”记录告警，并保留原有身份、姿态和语义检查，不把“未检查”记作“已保持”。
6. API 2.25.5 增加双向强阻断：除原有的“黑白灰宠物被改成暖色”外，暖色被毛占比显著流失并转成灰白、或低灰黑源图突然扩张出大面积灰黑纹路，也会直接拒绝。
7. 全身签名额外统计主体内部的局部暗带拓扑；源图没有条纹时，候选新增多条细长高对比暗带会记录为 `invented_stripe_pattern`。该检测忽略眼鼻和主体轮廓阴影，并按组件数量、面积和局部对比联合判定。
8. canonical 候选触发上述任一问题后会继续执行全部安全重试；必要时可对原始上传图做语义抠图，但该结果只能作为后续五轮动作生成的身份输入，不能直接发布或作为终端降级输出。暖棕、浅金和奶油色统一按相邻暖色被毛家族描述，不再把金毛错误写入 `golden fur` 负面词。

API 2.21.2 对“消色猫”使用以下条件：消色比例至少 `0.72`，且原图暖色比例不高于 `0.12`；或暖色比例不高于 `0.14` 且高饱和暖色比例不高于 `0.03`。第二条只吸收低饱和摄影光偏，不会把本身带高饱和橙棕色块的三花参考图误归为黑白灰猫；将灰白原图生成成暖棕/橙色角色仍会在进入姿态阶段前被拒绝并重试。

正向提示词还执行严格的道具语义隔离：奔跑和趴卧的首帧、构图、纠姿重试及 Wan 定位提示中不得出现 `bowl` 或任何食盆、水盆互动描述；只有吃饭和喝水分支可以加入对应的单碗规则。通用负面提示词中的“重复食盆”等排除项不属于正向动作语义。

基准严格加载 `宠物小猫 _ 写实摄影_v3.0.safetensors=0.50` 和 `Qwen Image-Kitten Photography_QWEN-小猫摄影.safetensors=0.60`，总权重 `1.10`，与源任务一致。只使用这套默认基准且没有用户额外上传 LoRA 时，基准图与四种姿态的所有重试都锁定为精确 `0.50 / 0.60`，只改变 seed、步数与纠错提示，不再静默降权或移除任一模型。用户自行替换或叠加 LoRA 时仍使用通用的同比降权安全回退，避免未知 LoRA 组合阻塞任务。图片和视频使用基准及其叠加模式时都不会额外加载全局内置风格 LoRA。

中文 `prompt` 和中文 `poses` 会先转换成英文再送入 Qwen/Wan。通用基准和四个内置姿态使用人工确认的固定中英映射；自定义中文姿态使用服务器本地 `Helsinki-NLP/opus-mt-zh-en`。任务状态同时保留 `prompt_original`、`prompt_en`、`poses_original`、`poses_en`、`image_profile_revision`、`pose_prompt_source`、`pose_preset_ids`、`identity_palette_guard`、`identity_palette_policy`、`source_identity_palette`、`effective_canonical_identity_palette` 和姿态毛色告警计数，便于历史审计。

直接调用接口时可传：

```bash
-F 'request_kind=video' \
-F 'image_profile=pet-multipose-20260717-v2'
```

省略 `image_profile` 会使用默认基准；显式传空字符串 `image_profile=` 可关闭该基准。健康检查会同时验证离线翻译模型和基准 LoRA 文件。

API 2.18 保留图片抠图失败时返回未抠图原图、视频任务正常报错的异常策略。语义抠图只处理真正的绿幕失败，不尝试修复缺腿、腾空、错误姿态或毛色漂移；奔跑首帧不合格时会直接返回真实姿态原因。启用 v2 且源图调色板可用时，只允许返回通过毛色检查的候选原图，不会为了绕过抠图失败而退回到已判定毛色漂移的首轮结果。多轮失败信息会分别标注 `persistent`（每轮持续出现）与 `transient`（仅特定轮次出现），避免把一次绿幕异常误报成所有轮次的共同原因。

### 生成普通 MP4

不传 `output_format` 时默认输出 MP4：

```bash
curl -sS -X POST 'https://ai.hzzootech.com/api/local-video/jobs' \
  -H "X-API-Key: $API_KEY" \
  -F 'generation_mode=keyframe_video' \
  -F 'image=@/path/to/reference.jpg' \
  -F 'prompt=保持同一只宠物身份和毛色，在摄影棚中自然运动' \
  -F 'poses=["正面坐姿并轻抬前爪","侧面站姿并缓慢转头"]' \
  -F 'resolution=720p' \
  -F 'output_format=mp4'
```

普通 MP4 支持 `720p`（1280×704）、`480p`（832×480）和 `512x512`。Wan2.2 I2V-A14B 与 TI2V-5B 的生产配置统一为 121 帧、24 FPS，单段约 5.04 秒；帧数必须满足 `4n+1`。透明输出再按完整时长选取 100 帧，编码为 20 FPS、5 秒 GIF/APNG；单任务最多 6 个姿态。
